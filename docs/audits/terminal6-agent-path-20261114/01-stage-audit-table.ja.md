# 01. S01〜S08 工程別監査表

判定基準は依頼どおり。`PASS` 公開資料と実装で手順・検証条件が揃う / `PARTIAL` 進められるが重要な不足 / `BLOCKED` 次工程に必須の条件が欠ける / `UNVERIFIED` 資料上は成立するが実機証明が不足。**机上のPASSは実機のPASSではない。この表に PASS はない。**

## 総括表

| 工程 | 判定 | 実機証明 | 主な理由 | 改善分類 |
|---|---|---|---|---|
| S01 UART接続 | **PARTIAL** | 設定値のみ観測済 | 物理接続・期待ログの記述不足（所有者作業は意図的に対象外） | A, D |
| S02 LK識別 | **PARTIAL** | プロンプトのみ観測済 | LKの安全/禁止コマンド一覧なし、期待バナーなし | A, B |
| S03 slot B Emergency Shell | **BLOCKED** | 研究個体で観測 | 到達手順・slot切替手順が公開側にない | B, D |
| S04 SSH（現在のブート） | **BLOCKED** | 研究個体の個別実績のみ | 新規個体向け一般手順なし（公開資料も NOT_VERIFIED と明記） | B, C, D |
| S05 SSH永続化 | **BLOCKED** | 2研究個体で個別に観測 | 公開手順なし、2手順は個体固有、電源再投入後の回帰履歴あり | B, C, D |
| S06 パーティション読取り評価 | **BLOCKED**（未分割） / PARTIAL（分割済み） | なし | 未分割を調べる実装がない、使える工具が公開されていない | B, C, D |
| S07 P43縮小・P44作成 | **BLOCKED** | なし | `--apply` 拒否（正しい）、実機の定数・電源断・未分割は未検証 | C, D |

## S01 serial_link — PARTIAL

| 観点 | 評価 | 根拠 |
|---|---|---|
| 資料発見 | OK | 入口JSON → `START-HERE.ja.md` §1 → 実測JSON `connection` |
| コマンド・環境・成功判定 | 一部不足 | 115200 8N1・フロー制御なし・3.3V TTL・単一オーナーは明確。**成功の判定が「起動ログが読めること」のみ**で期待文字列がない |
| 公開資料のみで実行可能 | 部分的 | UARTパッドの位置・配線図・分解手順は**公開にも非公開記録にも存在しない**（基板リビジョン差があるため所有者が現物で確認する方針） |
| 欠落・循環 | なし | |
| 個体差 | 注意喚起あり | 配線は現物確認と明記 |
| 失敗時の安全停止 | OK | 電圧が不確かなら停止（`stop_conditions` に明記） |
| 実機検証と推測の区別 | OK | 設定値は `confirmed_on_unit` と明記 |

**不足:** 期待される起動ログの特徴（匿名化した要約）、ホスト側のシリアル取得ツール指定（エージェントが自前のものを使う前提）、ログ保存の注意（秘密情報を含み得る）。
**物理作業は OWNER_ONLY** であり、AIが担えないことは仕様として正しい。

## S02 lk_identify — PARTIAL

| 観点 | 評価 | 根拠 |
|---|---|---|
| 資料発見 | OK | 実測資料 §1 の識別表 |
| 成功判定 | 弱い | 識別子は **`]` プロンプトのみ**。バナー・バージョン文字列の例がない。「プロンプトだけでシェルを推定しない」という原則と、識別がプロンプトに依存する点が噛み合わない |
| 安全性 | **不足** | **LKは eMMC への生書込みコマンドを持つ**（非公開の履歴で、ブート制御領域の書換えとその副作用が記録されている）。公開側に「LKで使ってよい読取り専用コマンド」「使ってはいけない書込み系コマンド」の区分がない |
| 個体差 | 一部 | Ctrl+C のタイミングは「観測例」止まり |

**不足:** LKコマンドの許可/禁止区分（読取り専用のみ列挙）、LK版識別のための匿名化ログ例、書込み系コマンドを AI が自律実行しないという明示の禁止。

## S03 stock_emergency_identify — BLOCKED（最初の BLOCKED）

| 観点 | 評価 | 根拠 |
|---|---|---|
| 識別基準 | **PASS相当** | `uname -m`=aarch64、cmdline の `bootslot=b`、PID1=`sh`、`init=/bin/sh`、OpenWrtとの非曖昧性。実測資料と workflow JSON で一致 |
| **到達手順** | **欠落** | Emergency Shell へ**どう入るか**が公開側にない。入口JSONは「識別」しか述べない |
| **slot B への切替** | **欠落・高リスク** | 起動中のslotが A の個体で B へ入る方法は公開側になく、非公開側の唯一の記録は**ブート制御領域の生書込み**。`success` フラグを先に立てると自動復帰が効かなくなる、書込み直後のダンプでは検証できず次回ブートのログで確認が必要、などの教訓がある |
| 承認設計 | OK | 「boot selection」は明示承認ゲート |
| 個体差 | 未検証 | 初期状態（active slot・retry値）が個体ごとに異なる可能性。他個体の値の流用は禁止と明記されているが、代替の読取り手順がない |

**BLOCKED の理由:** 識別基準だけでは次工程に必要な状態（Emergency Shell・slot B）へ到達できない。有能なエージェントが LK の `help` から手順を**自力発見する可能性**はあるが、それは文書化された安全手順ではなく、ブート制御の誤操作リスクを AI の推測に委ねることになる。
**必要な作業:** 所有者の判断で公開してよい粒度に整理した到達手順（読取り専用で現在のslotを確認 → 必要なら承認つきでslot選択 → 次回ブートのログで検証）。生書込みを伴う手順は、公開する場合でも明示承認・バックアップ・復旧経路を必須にする。**手順の公開可否は所有者決定。**

## S04 stock_ssh_session — BLOCKED

| 観点 | 評価 | 根拠 |
|---|---|---|
| 公開側の自己申告 | 正確 | 「Emergency Shell からの一時SSH開通は NOT_VERIFIED」と明記 |
| 非公開の実績 | 個体固有 | 一時SSH復旧スクリプトが存在するが、ブリッジ/VLAN設定・管理PCの送信元IP・ファイアウォール挿入位置・RAM上のホスト鍵・PTY用デバイス準備など**個体と管理ネットワークに依存する値**を前提とする。別系統の手順は公開されていない初期アクセス手段に依存する |
| Emergency Shell の制約 | 実測あり | `devtmpfs` なし、ルートは読取り専用 squashfs、ホスト鍵がプレースホルダ（0バイト）のままだと Dropbear が起動直後に終了する、`/dev/null` なし |
| 認証 | 注意 | 通常ログインの資格情報は不明が前提。鍵認証のみで一時起動する設計は妥当だが、新規個体では鍵配置が手作業 |

**BLOCKED の理由:** 新規個体に適用できる一般手順が存在せず、公開資料もそれを認めている。
**必要な作業:** 個体値を引数化した RAM 完結の一時SSHテンプレートの実装（C）、公開してよい部分の抽出（B）、新規個体2台以上での実機検証（D）。

## S05 stock_ssh_persistence — BLOCKED

| 観点 | 評価 | 根拠 |
|---|---|---|
| 公開側の自己申告 | 正確 | 「永続化手順は NOT_VERIFIED」「S04 の成功は S05 ではない」 |
| 非公開の実績 | **2系統・個体固有** | (1) 保存データ領域（P43）内にシードを置き、周期処理で再配置する方式: 通常再起動後の復帰を観測（旧FW・A号機）。(2) 純正 slot B のオーバーレイ内の起動スクリプトと限定ファイアウォール設定: 通常起動後の鍵SSH再接続を1回観測（C号機） |
| 弱点 | 重大 | (2) は**過去に「再起動後は成功、電源再投入後は不通」と報告された履歴があり原因は未確定**。直近の確認も `reboot -f` 1回で、UARTログがなく、S99の実行順を独立追跡できていない。どちらも**新規個体ではない** |
| ファームウェア差 | 未検証 | 入口JSONのとおり、新しいFOTA版で旧版の挙動が成立する保証なし |
| 公開側の欠落 | あり | 入口の `preconditions` は「persistent store and rollback plan identified」だが、**候補の保存先を一つも挙げていない**（初見AIが発見できない） |

**重要な相互依存:** 方式(1)は P43 を永続化の保存先にする。**S07 で P43 を縮小・再構成すると、シードの保全が S05 の成立条件になる。** 公開資料はこの結合に言及しておらず、S06 の事前条件に「P43 使用量が縮小先（440MiB）に収まること」も入っていない。
**必要な作業:** 永続化方式の一般化設計の整理（B）、新規個体での検証（D）、電源再投入を含む受入手順（C）。

## S06 partition_readonly_assessment — BLOCKED（未分割）/ PARTIAL（分割済み）

| 観点 | 評価 | 根拠 |
|---|---|---|
| 工具の公開状態 | **利用不可** | v0.4 r3 は入口JSON上「非公開の候補」。公開側にあるのは QEMU 専用スクリプトのみ（`/dev/vda` 固定） |
| **未分割への対応** | **実装上不可** | r3 の preflight は P44 の存在と正確なセクタ数を要求し、無ければ終了する。**未分割を読み取り専用で調べるモードがない**（04 の X02 参照） |
| 必要コマンドの有無 | 未確認 | preflight は `e2fsck`・`blkid` を使うが、同梱ランタイムは `resize2fs`/`sgdisk` のみ。純正 Emergency Shell での存在は未検証（ELF実行 NOT_TESTED） |
| 開発個体自身での成否 | 不合格が既知 | 分割済みの開発個体では `e2fsck -fn` の所見により preflight 自体が拒否する（原因未確定）。**この工程が一気通貫で完走した実績はない** |
| 取得すべき情報 | 未定義 | P43 の使用量、journal 状態（要回復か）、GPT 両ヘッダの CRC、ext4 機能フラグ、開始LBA/GUID、ライブ個体のバックアップ可否 |

**必要な作業:** 未分割向け読取り専用監査モードの実装と受入基準（C）、ランタイムの補完とライセンス整理（B, C）、実機での読取り専用実行（D）。

## S07 partition_mutation — BLOCKED

| 観点 | 評価 | 根拠 |
|---|---|---|
| `--apply` | 正しく拒否 | 終了コード77。解除は不可（この監査でも解除していない） |
| QEMU検証 | あり・限定的 | 2.94GiB→440MiB 縮小・GPT分割・P44作成・200MiBペイロードのSHA保持・工程境界での停止再開（公開資料） |
| **実機に使えない理由** | 多数 | 定数の固定（P43開始LBA、セクタ数、GUID、`/dev/vda`）、P1〜P42省略、**書込み途中の電源断未試験**、**未分割実機未試験**、P43 使用量の事前確認なし |
| 縮小先の妥当性 | 未検証 | 縮小先 440MiB は分割済み個体の実測値。**未分割の新規個体の P43 使用量がそこに収まる保証がない**（QEMU 試験の使用量は約 70,933/112,640 ブロック） |
| 幾何の出典 | 注意 | 縮小前 P43 の大きさ（6170496 セクタ）は、研究個体の全量取得記録に由来する。A/B との比較は非公開側で「未比較」 |
| 復旧設計 | 不足 | バックアップは「必須」と書かれるが、**UART で P43 を退避する現実的経路がない**（約2.9GiB）。SSH 経由の退避が前提と読めるが、S04/S05 が未達 |

**必要な作業:** 定数を排した生GPT駆動の実装（C）、擬似的な電源断注入試験（C）、実機での実施（D）。
