# Air Terminal 6 共通初期準備と公開方針

**決定日:** 2026-11-18  
**位置づけ:** OpenWrt / Debian 13に共通する「純正状態からの下ごしらえ」の案内。ファームウェア導入手順ではない。

## 公開場所と役割

- **共通初期準備の正本は [openwrt-terminal-6](../README.md) に置く。新しい独立リポジトリは作らない。**
- 初めて触る人は [START-HERE.ja.md](../START-HERE.ja.md) から入り、Windows/LinuxでのUART接続、純正OSの現物確認、SSH、P43/P44の前提を理解する。
- AIエージェントは [agent-entry.json](../agent-entry.json) と [共通ワークフロー](TERMINAL6-PREPARATION-AGENT-WORKFLOW.json) を参照する。JSONは実行権限でも完成インストーラでもない。
- 個体差・検証証拠は [UART・純正環境・P43/P44の実測ガイド](STOCK-UART-EMERGENCY-P43P44-EVIDENCE-20261113.ja.md) と [実測JSON](STOCK-UART-P43P44-EVIDENCE-20261113.json) に集約する。
- 再利用可能な初期準備用ソース・試験を公開する場合も、このリポジトリの既存の `tools/`・`tests/`・`docs/` を優先する。個別OSの移植・起動手順は各リポジトリに置き、Debian側から共通入口へリンクする。
- 将来、初期準備が別の保守・リリース体系を必要とする規模になった場合にだけ、リポジトリ分離を再検討する。

## 共通初期準備の到着点

対象は、本人が所有または正当な管理権限を持つAir Terminal 6。正しい3.3V TTL UART接続とOS・slotの識別から始め、純正slot Bの通常起動後も認証付きSSHを使える状態、元のP43データを保持した約2.5GiBのP44 ext4、GPTの整合性、再起動後の独立した確認を目標とする。

OpenWrt / DebianのP25/P26書込み、OS切替、ファームウェア署名、無線送信やモデム制御は**初期準備の範囲外**。純正slot Bを復旧手段として保全する。実機で未検証の操作を、一般利用者が安全に実行できると表現しない。

## 公開する情報と公開しない情報

| 区分 | 方針 |
| --- | --- |
| 公開する | 独自に記述した手順書、匿名化した実測、合法的に再配布できるOSSコード・パッチ・テスト、出自とライセンス、確認済みの成功・失敗条件 |
| 状態を明記して公開 | QEMUのみの試験、未完成のツール、実機で未検証の分岐。**DRAFT / BLOCKED / NOT TESTED** を明示し、完成機能と区別する |
| 個別の配布判断が必要 | 実験用ファームウェアイメージ、実機へ書き込むツールや復旧資産。出自・権利・ライセンス・復旧条件・対象機体での検証を確認し、別途判断する |
| 公開しない | 秘密鍵、署名・認証の非公開基盤、鍵の入手経路、機体固有の認証情報や校正値、生の純正ファームウェアダンプ、非公開資産の内容、未公開の脆弱性の詳細やroot取得手順 |

問題の報告は [SECURITY.md](../SECURITY.md) に従って私的に扱う。第三者の権利や秘密に抵触しない範囲では、実験用資産の由来、確認できたこと、確認できていないこと、危険性、必要な復旧条件をできるだけ明らかにし、利用するかは所有者自身が判断する。**情報提供と実行の推奨・代行を混同しない。**

## 現在の公開物の限界

- 入口と読取り専用の観測資料は公開済みだが、**初期中古機で純正SSHを設定・再起動後に永続化する汎用手順は未立証**。
- **未分割実機のP43縮小・P44新設を安全に完走する一般向けインストーラは未検証**。P44がなければ、現状の一般向け手順では書込み工程へ進まず停止する。
- 開発機やQEMUでの成功は、別個体での成功を保証しない。復旧経路・バックアップ・現物確認・個別承認が揃わなければ書込み禁止。
- 公開済みのRC16実験版は [別のプレリリース](https://github.com/Karin-Laboratory/openwrt-terminal-6/releases/tag/sba6d-nora2-rc16-20261110-r1) であり、初期準備ツールを内包する一般用インストーラではない。

## 更新・公開の運用

共通の説明は一か所を正本とし、Debian側に本文を複製しない。公開前にリンク、文書の整合性、機密・個体固有情報の混入、第三者コードの権利、PASSと未検証の区別を確認する。新しい実機成果が得られたら、根拠と対象条件を記して入口・観測資料を更新する。破壊的作業の許可は文書公開によって発生しない。
