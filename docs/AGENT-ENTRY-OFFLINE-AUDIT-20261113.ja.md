# Terminal 6 初見AI入口：オフライン突合監査 (2026-11-13)

## 対象と方法
公開 `START-HERE.ja.md`、`docs/TERMINAL6-PREPARATION-AGENT-WORKFLOW.json`、`docs/STOCK-UART-P43P44-EVIDENCE-20261113.json`、PR #182、およびオーナー管理の非公開履歴（P43/P44候補PR #150、Debian C号機PR #155）を文書上で照合。**実機・UART・SSH・ストレージへのアクセスや操作は行っていない**。非公開アセット/原ログを公開せず、公開可能な事実と工程の境界だけ整理した。

## 判明した取り違えと修正
| 問題 | 非公開履歴との突合結果 | 入口JSONでの対処 |
|---|---|---|
| RC16配布とP43/P44分割工具を一体と誤認 | P43/P44 v0.4 r3は非公開候補で、公開RC16に同梱されていない | `concrete_tool_status` に別資産・配布条件を明記 |
| QEMU PASSを未分割実機の成功と誤認 | 疑似UART全量/再送/SHA・QEMU arm64起動の検査はあるが実機一気通貫/未分割変更/電源断復旧は未立証 | `--apply`拒否を尊重し、書込みはBLOCKED |
| 研究機stock SSH成功を全中古個体で使えると誤認 | Stock normal Bの公開鍵SSHは個体実績。初入手FWでの構築・永続化レシピは未確立 | S04の単発接続とS05の再起動後確認を区別 |
| Debian C号機の成功をStock下ごしらえへ転用 | slot A Debian + P44のEthernet/SSH/Wi-Fi PHY成功は、Stock slot Bの初期SSH/P43分割とは別成果 | 相互転用を禁止、OS/slotの実測同定必須 |
| データ保持とGPT認識だけで完了扱い | P43はmount状態/journal/fsck所見に注意。既存P44なら上書き禁止 | 分岐判定とS08で独立証拠を要求 |
| JSON入口だけでシリアル操作できると誤認 | ローカルPC・物理配線・シリアル操作ツール・所有者承認が別途必要 | `agent_modes` と `BLOCKED_CAPABILITY` を追加 |
| 承認済みだから未検証工具を動かしてよいと誤認 | 承認と実装検証は別条件。公開されていない秘密資産にも依存できない | 未実証の適用・復旧をBLOCKED、再評価必須 |

## 初見AI用の判定演習
`agent-entry.json#audit_scenarios` のT01〜T07を用意した。現状の試験は **静的な判定表と入口参照の整合検査**であり、言語モデルへ投入して独立評価したこと、機体操作に成功したことを意味しない。

## 実施した静的QA
- 入口JSONを正規ワークフローのS01〜S08と接続。資料パス、連番の初期行動、停止分岐、承認条件、非公開候補ツールの状態を検査。
- `tools/qa/test_onboarding_contract.py` に入口JSONを対象とする整合性アサーションを追加。
- `.github/workflows/onboarding-docs-qa.yml` の監視パスへ入口JSON、手引き、監査記録を追加。
- GitHub Actionsの実行結果は別途確認するまでPASSとは記載しない。

## 未解決（実機側の完成条件）
1. 初期個体・ファームウェア差のあるstock Bで、安全なSSH設定と再起動永続化の再現性を確認。

3. UART転送/ランタイムの完全な実機通し試験と、既存P44・異常FS・未知GPTの安全停止検証。
4. 初見エージェントへURLのみを渡したブラックボックス監査（根拠の誤転用・誤PASSを含む）。

## 公開境界
非公開PRの観測を公開可能な範囲で要約しただけで、private URL/asset、署名・復旧の保護された手段、個体固有値、未公開の脆弱性・root取得手順、OEM資料は依存先や配布物にしない。

**総合評価:** 機械可読の入口とSTOP条件は改善。初見AIにとって実行可能な全工程が揃ったという判定はまだ不可。実機未検証の工程は明示的BLOCKEDとして記録する。
